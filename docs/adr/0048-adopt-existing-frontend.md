# ADR 0048　产品主导项目的前端纳管

日期为 2026-11-17，状态为已实现、待合并评审。

产品可先在独立前端仓开发，再由有项目创建和清单同步权限的操作者登记项目。前端仓的 `docs/kaiwu-project-blueprint.json` 保存项目编码、名称、模板版本、初始化标识。兼容已提交的 Git 前端，蓝图缺少初始化标识时，CLI 从项目编码和仓库根提交计算身份。业务页面、服务契约、产品规则、验收场景及 `kaiwu/*.yml` 由该仓维护。

`project adopt <前端仓>` 预览。`--apply` 登记前端的 Git origin（如有），计划并应用项目清单和角色授权，然后创建或恢复 `ADOPT_FRONTEND` 任务，只交付独立后端。普通双仓生成沿用 `BASIC_SCAFFOLD`。项目编码冲突、已有业务目录不匹配或已有其他类型的一次性任务时，CLI 终止并保留现场。纳管复跑依据初始化标识识别新建的项目；平台描述包含此标识，手动改动描述会使再次纳管停止。

首次同步以平台成功移交记录为准。首次没有差异也保存成功记录；首次同步失败时，重跑仍导入角色。已有成功记录或已有配套后端生成任务时，纳管的预览和执行均只处理普通清单，保留平台调整过的角色授权。

应用后，业务侧继续从原仓运行前端，用 `project sync <前端仓> [--apply] [--with-access]` 同步后续配置。后端门禁用 `kaiwu/frontend-manifests` 定位清单来源；CI 联合校验时同时检出前端，设置绝对路径 `KAIWU_FRONTEND_DIR`。前端用 `KAIWU_SERVICE_DIR` 指向已实现接口的配套后端。后端脚手架从空模块起步，业务开发根据同一份规则和场景实现服务端校验。

`workflow sync <前端仓>` 单独访问业务项目的 Workflow 服务，预检发起权限、审批角色和当前绑定，`--apply` 只对新增或更新项发布。Workflow 记录上次导入的修订；当人工调整了绑定时，当前计划报告漂移并保留平台版本。

System 的 V128 为生成模式字典增加选项，Workflow 的 V22 保存项目内的导入回执。两者分别跟随各自服务发布。
