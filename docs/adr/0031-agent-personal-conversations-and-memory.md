# ADR 0031：Agent 个人会话、聊天记录与记忆

- 状态：Accepted（基于用户要求继续完善会话、聊天记录和记忆）
- 日期：2026-09-25

## 决策

1. 聊天窗口直接提供新建会话、分页会话列表、重命名、删除、历史加载和个人记忆管理，不跳转独立后台。最多保留100个会话；每页20个会话、每页30轮问答，支持加载更早记录。
2. System MySQL 是个人聊天的事实源，V58 增加 conversation/message/memory 三张表。所有接口沿用 `system:agent:ask`，归属只取受信 `StarterContext.userId`，不可传入 userId 选择数据。管理员也不能借此接口浏览别人的记录。网关登录会话和聊天会话是两个概念，不更改登录认证链。
3. 每轮持久化用户问题与助手文本。查询明细卡、表单值、操作令牌、确认短语和原始能力返回值均不落入聊天记录。操作预览保存为明确的非执行结果说明；恢复历史后不会显示可再次确认的卡片，实时数据和实际操作状态必须重新查询。历史文本是用户曾获得的历史记录，不是实时业务事实。
4. 个人记忆由用户在表单中显式添加、修改、启停或删除，最多20条、每条500字。不自动抽取聊天、自动记住秘密或修改授权。会话可单独关闭记忆；删除会话不删除长期记忆，两者删除入口分别确认。
5. 模型只接收该会话最近4轮已完成问答（每个答案最多2000字）以及当前启用的个人记忆。更早记录仍可翻页阅读，但不自动作为模型上下文。持久会话不接受浏览器提供历史或偏好，历史与偏好作为不可信数据拼入独立提示词区；能力目录裁剪、参数校验和执行前鉴权保持不变。
6. 每个客户端提交带唯一 requestId。短事务锁住归属会话、拒绝重复请求、持久化未完成消息，并写入5分钟处理租约；等待模型时不占用数据库事务。完成写回要求 runId 匹配，过期旧任务不能覆盖新轮次。服务重启或网络断开留下的未完成记录不会自动重发，UI 提示检查实际状态。
7. 前端账号切换/退出清空当前内存内容，迟到响应用 generation guard 丢弃；不把个人记录、访问令牌或确认令牌写入浏览器持久存储。

## 验证与发布

- V58 为增量新表，旧应用可继续运行；SQL快照与Helm副本同步。
- 发布顺序必须 System 后 Web：新 Web 依赖个人会话接口，不能只同步数据库文案就提前发布。
- 验证跨用户读写/删除拒绝、并发和重复消息、runId保护、分页、删除级联、记忆数量上限、启停和未完成记录；真实MySQL覆盖V57升级V58、完整迁移及二次无变化。
- 浏览器覆盖恢复历史、刷新、后续消息、新建隔离、重命名/删除、记忆CRUD和拒绝访问；保留原有创建项目/远程预览确认回归。

## 当前限制

旧版只驻留浏览器内存的聊天无法追溯补存。本轮不实现自动语义记忆、向量检索、多人共享会话、会话导出或后台管理员查看他人历史。删除个人历史不会抹去原有业务操作审计记录。
