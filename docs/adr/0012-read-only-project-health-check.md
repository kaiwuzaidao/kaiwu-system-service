# ADR 0012：只读项目体检

- 状态：Accepted
- 日期：2026-08-06
- 决策范围：`kaiwu-system-service`、`kaiwu-system-web`
- 保留：ADR 0006 的「生成后平台退出写入权」、ADR 0002 的独立仓库边界
- 补充：ADR 0009 的模板版本演进

## 背景

ADR 0006 让平台在一次推送后永久放弃对业务仓库的写入权，这消除了模板覆盖人工代码的路径，
但同时产生一个盲区：**平台不知道交付出去的项目后来变成了什么样**。

生成时的结构一致由确定性模板保证；第 2 天起的一致性依赖两样东西——业务仓库里的门禁脚本
（`check-permission-seed.sh`、`check-test-baseline.sh`、`check:dict`、`check:perm`）和
`AGENTS.md` 约定。这两样都在业务仓库内部，**都可以被删掉**，而删掉之后 CI 依然全绿。
多 AI 多轮迭代时，"门禁挡路就删掉"是成本最低的一条退化路径。

平台愿景承诺"多轮迭代后依然可运行、可维护、可升级"，但目前没有任何机制能观察到这件事
是否成立。「不写回业务仓库」和「不观察业务仓库」是两个不同的约束，ADR 0006 只要求前者。

## 决策

### 1. 只读，且只读契约面

平台可以**读取**已绑定 GitLab 仓库的少量固定文件，永远不写：

| 文件 | 用途 |
|---|---|
| `docs/kaiwu-project-blueprint.json` | 模板版本、契约版本、模块与权限前缀 |
| `.gitlab-ci.yml` | 门禁是否仍在流水线里 |
| `pom.xml`（后端根） | Starter 版本、JDK 版本 |
| `package.json`（前端根） | 门禁脚本是否仍在 scripts 里 |

**不读业务源码**，不 clone 整仓，不遍历目录树。理由有三：业务代码可能含平台无权查看的
内容；读得越少越不会变成事实上的代码托管；上述四个文件已经足以判断契约面是否完整。

### 2. 只存结论，不存内容

体检结果只落盘检查项、结论（`PASS` / `WARN` / `FAIL`）、发现的版本号和一句说明。
**读到的文件内容不入库、不进日志、不返回给浏览器。** 这样体检记录本身不会成为业务代码
的副本，也不会因为平台库泄露而外溢业务信息。

### 3. 触发与授权

- 由项目 owner 在平台上显式触发，或由平台按项目粒度的开关定时执行。
- 项目 owner 可以**关闭**本项目的体检；关闭后平台不再访问该仓库。
- 复用 ADR 0006 已有的受管 GitLab 配置与加密 Token，不新增凭据、不接受用户临时填写的
  Token。Token 仍然只发往配置中相同 scheme/host/port/base-path 的 GitLab API。
- 未绑定 GitLab 仓库的项目（只下载 ZIP 的）不参与体检，状态为「无法体检」而不是失败——
  平台看不到的东西不能当成不合格。

### 4. 体检只报告，不阻断

体检结果不影响任何流程：不阻断部署、不改变项目状态、不触发通知以外的动作。
它是给人看的健康度信号，不是第二套准入控制。

理由：平台无权改业务仓库，因此任何"阻断"都只会变成一个业务团队无法自助解决的死锁。

### 5. v1 检查项

| 检查项 | FAIL 条件 | WARN 条件 |
|---|---|---|
| 契约清单 | `kaiwu-project-blueprint.json` 缺失或非法 JSON | — |
| 后端门禁 | `.gitlab-ci.yml` 不再调用权限、约束目录或 Gitleaks 门禁 | 不再调用测试基线报告 |
| 前端门禁 | `package.json` 缺 `check:perm` 或 `check:constraints` | 缺 `check:dict` |
| 模板版本 | — | 低于平台当前 `TEMPLATE_VERSION` |
| Starter 版本 | — | 低于平台当前发布版本 |

FAIL 表示"契约面已被破坏"，WARN 表示"可以升级但不影响正确性"。**版本落后只报 WARN**：
平台无权也不应该要求业务项目跟随升级。

## 后果

### 正向

- "多轮迭代后是否仍然一致"从愿望变成可观测的事实。
- 门禁被删这类退化第一次变得可发现，而且不需要平台拥有写权限。
- 只读四个文件的边界让体检的成本、风险和心理负担都足够低，业务团队更可能保持开启。

### 成本与限制

- 体检看不到业务逻辑正确性，也看不到未推送到默认分支的改动。
- 依赖 GitLab 可达；不可达时结果是「未知」，不得当成失败。
- 平台需要长期维护"当前模板版本 / Starter 版本"的事实来源，否则版本比较会误报。
- 关闭体检的项目等于自愿退出可观测范围，平台不做任何补偿性推断。

## 被否决方案

- **克隆整仓做静态扫描**：读取面过大，等于把业务代码搬进平台，且平台没有这个授权。
- **体检失败即阻断部署或标记项目异常**：平台无写权，业务团队无法自助修复到"平台认可"
  的状态，只会制造死锁。
- **平台自动补回被删的门禁文件**：直接违反 ADR 0006 的"生成后不再向仓库写代码"。
- **要求用户为体检单独提供 Token**：扩大 Secret 暴露面，且与已有受管 GitLab 配置重复。
- **把体检结果做成评分或排行榜**：会诱导为分数服务的改动，而不是真正的工程健康。
