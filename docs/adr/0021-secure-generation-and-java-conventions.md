# ADR 0021：生成项目资源授权、可靠异步投递与 Java 高信号规范

- 状态：Accepted
- 日期：2026-08-13
- 决策范围：Kaiwu 四仓、项目工厂模板与生成业务项目
- 补充：ADR 0003、ADR 0006、ADR 0020

## 背景

2026-08-13 的全工作区审查确认了三类可复现问题：

1. 项目生成和 GitLab 初始推送先持久化 `PENDING` / `PUSHING`，再向有界线程池投递；队列拒绝时
   没有补偿，任务只能等待进程重启恢复。
2. 生成 CRUD 只生成接口权限，没有表达记录是项目内共享还是仅归属当前用户；主键、归属字段、
   审计字段也可能进入保存请求。旧报销样例因此允许具有功能权限的成员按任意 ID 操作他人记录。
3. Kaiwu 没有采用可在 JDK 21 上稳定执行的阿里 Java 规范门禁，现有代码出现了 `SELECT *`、
   `Executors`、非托管后台线程等《Java 开发手册（黄山版）》明确禁止的写法。

官方 `p3c-pmd 2.1.1` 面向较老的 PMD/JDK 目标，不能直接作为 JDK 21、record 和文本块工程的
不可豁免门禁。Kaiwu 控制面保留数据库外键、Snowflake `BIGINT` 和既有时间/布尔字段命名也有
明确的完整性或迁移成本理由，不适合机械改表。

## 决策

### 1. 持久化状态与异步投递必须可补偿

- 任何先写数据库状态、再向内存执行器投递的流程，都必须捕获拒绝并把本次已抢占状态恢复为
  可重试失败状态。
- 补偿失败不得被吞掉；调用方得到 `503`，日志只记录任务标识和安全错误摘要。
- 必须有使用拒绝执行器的行为测试，分别覆盖首次生成、失败重试和仓库推送。
- 不使用 `CallerRunsPolicy` 把项目生成、打包或远端推送转移到 HTTP 请求线程。
- 本决策不引入通用消息队列、Workflow 或 Integration；吞吐量超过单机补偿模型时，再以真实容量
  证据决定数据库轮询或 Outbox。

### 2. 生成 CRUD 必须声明资源访问范围

每个生成表的蓝图和产物必须明确写出以下范围之一：

- `PROJECT_WIDE`：持有对应项目权限的成员可操作该表记录。
- `OWNER_ONLY`：除接口权限外，所有列表、详情、更新和删除都必须绑定当前 Gateway Context 用户。

确定性推导规则如下：表包含 `owner_user_id` 或 `global_user_id` 时生成 `OWNER_ONLY`，归属列不进入
外部保存请求，新增时由 `StarterContext.userId()` 写入；其它表生成 `PROJECT_WIDE`。模型不能提供
任意策略表达式，也不能改变这个推导结果。需要更复杂成员关系或资源状态的项目由业务团队在独立
仓库实现并补行为测试，不扩展通用策略引擎。

生成 API 同时遵循：

- 主键只来自更新/删除路径，不允许请求体选择待更新记录；
- 逻辑删除、自动填充时间和归属列不进入保存请求；
- Controller 使用 Bean Validation，数据库非空字段生成基础校验；
- `OWNER_ONLY` 的越权访问统一表现为资源不存在，避免泄露记录是否存在；
- 生成测试必须包含“另一用户不能读取、更新、删除”的反例。

### 3. 采用 Java 21 兼容的阿里规范高信号子集

《Java 开发手册（黄山版）》明确标为强制、且可稳定自动检查的两项分别登记为 MUST：

- `query.explicit-projection`：ORM 业务查询不得使用 `SELECT *` 或别名星号；
- `runtime.managed-threads`：生产代码不得使用 `Executors` 工厂方法，不得启动脱离生命周期管理的裸线程，
  线程池必须显式声明容量、线程名、拒绝策略和关闭行为。

另新增 `java.high-signal-conventions`，初始强度为 `WARN`，规则包括：

- 与协议、SQL 标识符和状态有关的大小写转换使用 `Locale.ROOT`；这是 Java 国际化/SpotBugs
  稳健性建议，不表述为阿里手册违例；
- 异常不得无说明、无观测地吞掉；
- 其它可由 JDK 21 工具链稳定检查、且不与 Kaiwu 架构决策冲突的高信号规则。

这些规则通过 Java 21 可执行的仓库约定测试、Spotless 和评审实现。WARN 项验证稳定后可逐条升级为
MUST，但不得直接启用无法正确解析当前语法的旧版全量 P3C PMD 规则集。

以下差异登记为 Kaiwu 项目级例外，不做存量破坏性迁移：

- 控制面数据库使用外键保证同库强一致性，但禁止级联删除；
- 19 位 Snowflake ID 使用 `BIGINT`，JSON/TypeScript 边界保持字符串；
- 存量 `created_at` / `updated_at` 及布尔列名保持兼容，新表继续遵循现有 Kaiwu schema 风格。

### 4. 供应链与验证入口保持声明和行为一致

- `security.supply-chain` 扩展到所有可交付平台仓库和生成仓库；各仓 CI 至少执行 Secret 扫描、
  依赖或文件系统高危漏洞检查并产出 CycloneDX SBOM。
- CI 注释、脚本阈值和实际退出码必须一致。需要临时接受 High 时，必须登记责任人、理由和到期日，
  不能靠注释声称只阻断 Critical。
- 每个仓库提供唯一 `verify` 入口，CI 和开发文档调用同一入口；入口在执行前校验 JDK/Node/pnpm
  主版本，避免用户级启动文件静默切换工具链。

## 后果

- 项目工厂在执行器过载时不会留下运行期无法重试的一次性记录。
- 新生成的用户归属表默认具有数据授权边界，项目共享表则明确承担项目级访问语义。
- Kaiwu 可以陈述“执行了选定且可验证的阿里规范高信号规则”，但不虚称全量 P3C 完全合规。
- 当前模板版本升级；既有 SUCCESS 项目仍不回写，旧报销样例必须由其业务仓库单独修复或明确归档。

## 回滚

- 异步补偿、门禁和模板变更可按仓库提交回滚，不修改已发布 Flyway 历史。
- 模板回滚只影响之后的新生成任务，不覆盖既有业务仓库。
- 资源范围只存在于蓝图和生成代码，不增加平台数据库结构，回滚不需要数据迁移。
