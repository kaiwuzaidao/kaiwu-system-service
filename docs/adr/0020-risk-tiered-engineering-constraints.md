# ADR 0020：风险分级的工程约束与模型无关开发

- 状态：Accepted
- 日期：2026-08-12
- 决策范围：Kaiwu 四仓、项目工厂模板与生成业务项目
- 部分取代：ADR 0002 的固定开发分支、ADR 0006 的固定初始推送分支、ADR 0008 的生成项目强制调度方式、ADR 0017 的“复杂 SQL 不使用 XML”
- 补充：ADR 0009 的模板版本演进、ADR 0012 的只读项目体检

> 2026-09-13 补充：第 8 节关于格式化强度的表述，在 Kaiwu 平台三个 Java 仓由 ADR 0029 取代——
> 那里 spotless check 绑定到 `validate` 并阻断构建。项目工厂模板与生成业务项目不变，
> 格式化仍是 `DEFAULT`。本 ADR 其余部分继续有效。

## 背景

Kaiwu 已经把鉴权、项目隔离、权限码、数据库迁移和生成交付沉淀为可执行门禁。这些规则防止了
真实的安全与数据事故，应继续阻断。但生成项目的协作契约也逐渐混入固定分支、测试类命名、
Javadoc 覆盖、调度实现、配置来源和双语同步等实现偏好。它们被写成同一强度的“必须”后，
不同团队和不同 AI Coding 工具只能复制平台当前写法，无法根据业务风险作出合理选择。

工程约束的目标是稳定结果，不是统一每一行代码的形状。本 ADR 将约束按风险分级，并提供有期限、
可审计的偏离方式。

## 决策

### 1. 三种约束强度

每条长期约束必须登记到 `docs/kaiwu-constraints.json`，并声明唯一 ID、强度、适用范围、理由、
执行方式、是否可豁免和复核日期：

| 强度 | 语义 | CI 行为 | 是否允许 waiver |
|---|---|---|---|
| `MUST` | 安全、数据、外部契约或可交付性的硬边界 | 失败阻断 | 不允许 |
| `WARN` | 有明确收益，但偏离不等于产物不安全 | 报告，不阻断 | 允许 |
| `DEFAULT` | 推荐实现和自动化默认值 | 提供自动修复或样例 | 允许 |

Markdown 负责解释“为什么”，JSON 是工具读取的单一目录。各仓 `AGENTS.md` 可以补充操作细节，
不得另造不同强度的第二份事实源。

### 2. 有期限的 waiver

可偏离规则写入 `docs/kaiwu-constraint-waivers.json`，必须包含 `constraintId`、`owner`、`reason`、
`expiresAt`。约束目录校验必须拒绝：

- 对 `MUST` 或 `waivable=false` 的规则创建 waiver；
- 不存在的约束 ID；
- 缺责任人、理由或到期时间；
- 已经过期的 waiver。

waiver 只说明团队显式承担某项非硬约束的偏离，不得关闭 Secret、鉴权、项目隔离、权限、迁移历史
或构建正确性门禁。

### 3. 分支策略归业务仓库所有

- Kaiwu 自身不再要求所有维护者使用某个固定的个人分支名；只要求不得直接在受保护分支实现。
- 新项目默认分支为 `main`，项目管理员可以在首次推送前修改 `defaultBranch`。
- Kaiwu 只向项目登记的目标分支执行一次空仓库初始提交，不规定团队后续采用 Git Flow、主干开发
  或其它分支策略。
- 已生成或已绑定仓库的分支不回写、不迁移，保持 ADR 0006 的平台退出写权限边界。

### 4. Flyway 约束确定性，不要求所有脚本可重复执行

Flyway 迁移保持前向、版本唯一、已发布不可修改，并在全新 MySQL 与升级样本上真实执行。取消
“所有增量必须幂等”的总要求：Flyway 本来只执行每个版本一次，普遍使用 `IF NOT EXISTS` 可能把
错误的存量结构伪装成成功。只有启动自举、可重复迁移或明确需要重试的 seed/补偿步骤才要求幂等，
并在脚本中写明原因。

### 5. 字典只约束用户可见且可运营的值

用户界面展示、筛选并需要翻译或运营配置的业务状态/枚举使用受管字典，未知值原样显示。内部状态机、
协议码、固定布尔逻辑和只参与分支判断的枚举保留类型安全的代码常量，不要求创建平台字典。

### 6. 测试与 API 兼容

- “每个 Controller/Service 必须有同名测试类”降为 `WARN`。脚本默认只报告；模板自验证可以使用
  `--strict` 保证首版测试骨架没有丢失。验收重点改为权限反例、领域行为和接口契约，而非类名覆盖率。
- `docs/api-contract.txt` 是最低兼容基线。新增接口或字段允许通过；删除接口、删除字段、改字段类型
  或改已有路径必须失败。确认发布新兼容基线时显式运行刷新参数并审阅 diff。

### 7. 文档、SQL、配置、调度与语言

- Javadoc 强制范围收窄到公共 API、SPI、Port、安全边界和难以从签名理解的行为；普通 public 方法
  不再以注释数量阻断构建。
- 数据层保持 MyBatis-Plus 单一 ORM。单表 CRUD 使用 `BaseMapper`；多表 JOIN、动态条件、报表等
  复杂查询优先使用 Mapper XML。已有高风险状态机/授权注解 SQL不做机械迁移，修改时单独验证。
- 平台参数配置和 Scheduler Starter 是生成项目的受管默认能力，不是唯一实现。领域不变量可以留在
  版本化代码/业务库；本地调度可以使用 `@Scheduled` 或其它实现，但多副本协调、幂等和运维责任必须
  在项目 ADR 中说明。
- 生成业务项目只要求其声明的 `supportedLocales` 完整。默认只启用 `zh-CN`；增加语言时再补齐该语言
  资源，不要求每次业务改动天然维护中英文两份文案。

### 8. 自动格式化与 Secret 扫描

- Java 生成仓库提供 Spotless 自动格式化入口，前端提供 Prettier 自动格式化入口。格式化属于
  `DEFAULT`，用于消除不同人员和模型的排版漂移，不承担架构评审职责。
- 新生成的前后端仓库都必须在 CI 运行 Gitleaks。Secret 扫描属于不可豁免的 `MUST`。
- 新生成仓库使用 Trivy 阻断未修复的高危/严重文件系统漏洞并产出 CycloneDX SBOM；当流水线
  提供 `KAIWU_IMAGE_REF` 时继续扫描实际镜像。供应链检查属于不可豁免的 `MUST`，但不产出镜像的
  合并请求不会伪造镜像扫描结果。

## 后果

- 安全和数据边界继续强制，不因模型或团队不同而降低。
- 业务团队可以选择分支、复杂 SQL、调度、配置和语言策略，不再被平台实现偏好锁死。
- 约束目录与 waiver 自身也由测试校验；规则增加、升级或降级都有可审阅的机器可读 diff。
- 项目模板升级为 `kaiwu-project-v4`。既有 SUCCESS 项目不回写，只在项目体检中看到版本差异。
