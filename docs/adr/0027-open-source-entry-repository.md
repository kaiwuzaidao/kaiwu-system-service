# ADR 0027：薄开源入口与产品仓库边界

- 状态：Accepted
- 日期：2026-08-14
- 决策范围：开源主页、首次下载、跨仓版本入口
- 补充：ADR 0002、ADR 0023、ADR 0026

## 背景

Kaiwu 的运行和部署能力分布在五个独立仓库。让第一次接触的用户先理解仓库关系、逐个克隆并
对齐版本，会把内部架构成本转嫁给使用者；但把五仓改成 monorepo 或要求用户掌握 Git submodule，
又会破坏既有独立版本、CI、权限和回滚边界。

`kaiwu-system-service` 已能自动获取运行 sibling，但它的 README 同时承担控制面后端说明，不能
完整承载开源项目主页、仓库导航、贡献入口和发行视图。

## 决策

### 1. 增加无产品源码的 `kaiwu` 开源入口

工作区增加 `kaiwu/` 目录，未来可独立发布为同名开源入口仓。它只保存：

- 项目主页和仓库地图；
- 贡献、安全与首次使用说明；
- 一个入口脚本和最小入口清单；
- 入口自身的静态自检。

它不保存 Java/TypeScript 产品源码、Helm Chart、环境 values、Secret、数据库 migration、生成
模板或业务项目配置，不成为第六个产品仓库。

### 2. 入口只克隆 System，再委托现有启动器

入口将工作副本放在自身忽略的 `workspace/` 中，首次只克隆 `kaiwu-system-service`，再调用其
`scripts/kaiwu.sh` 获取三个运行 sibling、生成本地密钥并启动平台。选择 Kubernetes 时仍由
System 启动器按需获取 `kaiwu-deploy`。

入口不得复制 Compose、Helm 或密钥生成逻辑。产品启动契约仍以 System 仓启动器为事实源。

### 3. 不把 submodule 作为用户必经路径

入口不提交五个仓库的 submodule。Release tag 自动传递给 System 启动器，使所有仓库使用同名
tag；Fork 或自建 Git 服务通过显式 base URL/ref 覆盖。实际 commit 仍由 System 启动器记录到
工作区锁文件。

维护者可以自行使用 submodule 管理镜像工作区，但公开快速开始不得依赖它。

### 4. 同名 Release 是兼容单元

`kaiwu` 入口与五个产品仓使用相同 Release tag。开发态可以使用默认分支，正式发布不得用浮动
分支冒充稳定发行。若任一必需产品仓缺少同名 tag，初始化应失败，而不是静默混用默认分支。

## 后果

- 用户只需发现和克隆一个仓库，五仓结构不再成为首次体验门槛。
- 主页可以从同一视角解释定位、架构、使用、贡献和部署路线。
- 多一条很薄的发布协调路径；Release 时必须确保六个公开仓同名 tag。
- `workspace/` 是可重建工作副本，不纳入入口 Git 历史，不承载用户业务源码。

## 不做什么

- 不把产品代码合并回入口仓。
- 不复制五仓 README、架构正文或部署配置形成第二事实源。
- 不让入口脚本修改已有仓库、force checkout 或覆盖用户分支。
- 不引入安装服务、遥测、远程命令执行或自动发布中心。
