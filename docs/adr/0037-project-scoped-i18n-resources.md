# ADR 0037：国际化资源按项目作用域隔离

- 状态：Accepted（V102 已落地）
- 日期：2026-10-28
- 决策范围：`kaiwu-system-service`（国际化、字典、配置、菜单、清单同步）
- 补充：ADR 0011、ADR 0013、ADR 0014、ADR 0015、ADR 0036

## 背景

ADR 0011 起，所有国际化资源存放在一张全局表 `sys_i18n_message`，`message_key` 全局唯一，
范围是"Kaiwu 平台自身"。ADR 0036 让业务项目通过清单为自己的字典标签、菜单名写入多语言文本，
如果继续放在这张全局表里，只靠 `proj.{项目编码}.` 前缀区分，会出现三个问题：

1. 平台文案目录接口返回全部启用资源，所有业务项目的文本都会下发到每一个平台用户的浏览器，
   并随项目数量增长；A 项目的字典标签对 B 项目的用户也可见。
2. 写入资源需要平台级权限 `system:i18n:save`，业务项目管理员为了同步自己项目的文本，
   就必须拥有修改整个平台文案的权限。
3. 平台的"国际化资源"管理页混入所有项目的条目。

字典与参数配置早已按 `scope_id`（`0` 为平台，项目 ID 为项目）隔离，国际化资源是唯一的例外。

## 决策

### 1. 表结构

`sys_i18n_message` 新增作用域列，唯一约束改为作用域内唯一：

```sql
ALTER TABLE sys_i18n_message
    ADD COLUMN scope_id BIGINT NOT NULL DEFAULT 0 COMMENT '0 为平台资源，其余为业务项目 ID' AFTER id;
ALTER TABLE sys_i18n_message DROP INDEX uk_sys_i18n_message_key;
ALTER TABLE sys_i18n_message ADD UNIQUE KEY uk_sys_i18n_message_scope_key (scope_id, message_key);
```

存量资源全部落在 `scope_id = 0`，语义不变。不新建表，不迁移数据。

### 2. 读取

- 平台文案目录（`/api/i18n/catalog`、`/api/public/i18n/catalog`）、平台国际化管理页、
  翻译导出与平台菜单/字典的体检查询只读 `scope_id = 0`。
- 解析某个作用域引用的 key 时，先查该项目的资源，再回退到平台资源。这与字典"项目覆盖全局"一致：
  项目可以复用平台已有的通用文本，也可以用同名 key 覆盖。
- 校验"引用的 key 必须存在"（ADR 0013 第 6 节）按同一规则：在本项目或平台存在即可。
- 字典项、字典名与配置值按其所在行的作用域解析；全局字典项仍只用平台资源。

### 3. 写入

- 平台资源仍由 `system:i18n:save` 维护，接口与界面不变。
- 项目资源只能由该项目的有效项目管理员写入，不要求平台级国际化权限。写入入口有两个：
  ADR 0036 的清单同步，以及国际化资源管理页的「所属范围」切换（`/api/projects/{projectId}/i18n/*`：
  列表、保存、删除、译文导出导入）。后者由 `ProjectI18nAccessPort` 校验目标项目的 ACTIVE
  project-admin，内置项目一律拒绝；项目资源强制 `public_visible=0`、`required_resource=0`，
  不参与平台语言开放门禁。项目译文工作簿只有「资源」一个 Sheet，只读写该项目作用域。
  平台入口按 `scope_id=0` 取资源，拿项目资源的 id 调用会得到「不存在」。
- 清单同步生成的 key 不再带 `proj.{项目编码}.` 前缀，例如 `dict.order.order_status.PAID`；
  清单同步也不再要求 `system:i18n:save`。

### 4. 缓存

平台目录缓存保持现状。项目资源按 `(项目, 语言, 目录版本)` 缓存，任一资源写入时沿用现有的目录版本号
递增，使平台与项目缓存一起失效。

## 被否决方案

- **继续用全局表加 key 前缀**：无法解决下发范围与权限过大两个问题。
- **新建项目文案表**：解析、校验、导出都要再写一套，与字典、配置的作用域模式不一致。
- **项目资源只在业务前端仓库维护**：字典标签与配置值由平台在服务端解析后下发（ADR 0014），
  业务前端拿到的已是最终文本，资源必须在平台侧。

## 后果

- 平台用户只下载平台文案；项目文案只在解析该项目的字典、配置、菜单时使用。
- 业务项目管理员同步自己项目的文案，不再需要平台级国际化权限。
- 一次 Flyway 增量改结构（不迁移数据）；国际化仓储、目录服务、字典/配置解析与清单同步需要相应调整。

## 迁移与回滚

- 存量数据全部为 `scope_id = 0`，升级不改变任何现有行为。
- 回滚时先删除 `scope_id <> 0` 的行，再恢复 `message_key` 单列唯一索引并删除该列；ADR 0036 尚未在任何环境落入项目资源，回滚无数据损失。
