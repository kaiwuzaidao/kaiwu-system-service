# ADR 0033：统一 Java 风格与中文 Javadoc

- 状态：Accepted
- 日期：2026-10-15
- 决策范围：Kaiwu 平台、Starter、Gateway、项目工厂模板及接入平台的 Java 后端项目
- 补充：ADR 0020、ADR 0021、ADR 0029、ADR 0032

## 背景

平台仓已经采用 Spotless 与 Palantir Java Format，但业务项目、旧模板和存量源码的格式化入口、
中文 Javadoc 覆盖和说明质量并不一致。不同维护者与多个编码代理协作时，缺失的职责、权限、
状态机和副作用说明会让评审只能从实现细节反推约束。

同时，直接把旧版全量 P3C/PMD 规则作为 Java 17/21、record 和 Spring Boot 4 工程的硬门禁，
会造成大量与风险无关的噪声。ADR 0021 已限定采用阿里规范中可稳定验证的高信号子集；ADR 0029
已选定 Palantir Java Format 作为平台仓唯一机械格式化器。

## 决策

1. 所有 Java 后端使用 Spotless 的 `palantirJavaFormat`；不得混用第二个格式化器。平台三仓继续在
   `validate` 阶段执行 `spotless:check`，业务项目保留 `mvn spotless:apply` 的确定性修复入口。
2. 所有手写 Java 类型、构造器和方法使用中文 Javadoc。注释说明职责、业务结果及必要的授权、
   数据范围、事务、幂等、审计、状态机、异常或外部副作用；覆写方法不因 `@Override` 获得豁免。
3. 类型命名、方法命名、常量、布尔表达、import、线程和 SQL 规则遵循
   [JAVA_STYLE.md](../JAVA_STYLE.md)；已发布 API、数据库列、SQL 标识符和序列化字段不做
   破坏性机械改名。
4. 中文 Javadoc 的“是否存在”可自动检查，但“是否真正解释了边界”仍由评审判断。存量按公开契约、
   安全写链路、Agent 能力、外部集成和内部辅助代码的顺序清理；不允许用批量生成的同义句宣称完成。
5. 项目工厂向新项目生成同一份规范与约束目录，因此新的业务仓不再从旧模板继承无统一风格的起点。

## 后果

- 代码排版可用一条命令稳定修复，中文文档的表达质量不被机械格式化器破坏。
- 新改动立即按统一规范评审；存量注释通过可复核批次收敛，避免一次性大范围无意义改写。
- 本 ADR 不改变 HTTP、权限、Agent 审批、数据库或部署语义。
